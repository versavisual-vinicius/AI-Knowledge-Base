# Revisão de etapa

Use quando uma etapa foi implementada ou quando o usuário pedir revisão do
projeto inteiro.

1. Confira o escopo, o critério de aceite e o diff da etapa.
2. Faça uma primeira revisão estrutural: arquivos, contratos, referências,
   estados e pendências.
3. Faça uma segunda revisão independente executando os checks pertinentes.
4. Corrija inconsistências encontradas e repita o check afetado.
5. Registre evidência, aprovação humana e o estado de publicação.
6. No encerramento, revise cada etapa desde a primeira duas vezes e compare
   decisões, status, documentação e artefatos publicados.

Não marque a etapa como aprovada apenas porque os testes passaram; a aprovação
humana e as limitações não validadas devem permanecer explícitas.
